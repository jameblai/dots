# NixOS dots

NixOS 26.05 and Home Manager configuration for the `cipher` workstation.

## What this config manages

- KDE Plasma 6 on Wayland with Plasma Login Manager
- NVIDIA stable driver using the open kernel module for the RTX 5070
- AMD CPU microcode and the AMD integrated GPU driver
- Steam, GameMode, Tailscale, 1Password, and YubiKey support
- Helium, Discord, Dropbox, TIDAL Hi-Fi, Telegram, and Yubico Authenticator
- Ghostty, tmux, Zed, VS Code, Neovim, zsh, and Prezto
- Git authentication and SSH commit signing through the 1Password SSH agent

The machine-specific entry point is `hosts/cipher`. User configuration lives in
`modules/home`, while reusable system services and desktop configuration live
in `modules/nixos`.

## Repository layout

- `hosts/cipher`: hostname, locale, hardware choices, and module composition
- `modules/nixos`: reusable operating system, desktop, program, and service configuration
- `modules/home`: Home Manager applications and user configuration
- `config`: configuration files consumed by Home Manager modules
- `justfile`: the supported build, validation, update, and activation commands

The flake also provides a development shell, Nix formatter, and checks for
formatting, dead Nix code, and common Statix findings.

## Before installing

Back up everything that matters. A clean NixOS installation can erase the
selected disk, and this repository does not manage partitioning or recovery of
existing CachyOS data.

Download the NixOS 26.05 Plasma graphical ISO, boot it in UEFI mode, and use the
graphical installer. Use these values during installation:

- User: `jamesblair`
- Hostname: `cipher`
- Desktop: Plasma
- Boot mode: UEFI

Disk layout and encryption are intentionally left to the graphical installer.
Secure Boot is not configured by this repository.

## First activation

After booting the newly installed NixOS system, open a terminal and clone this
repository to the path used by the shell aliases:

```bash
nix shell nixpkgs#git -c git clone <your-repository-url> ~/dots
cd ~/dots
```

Replace the committed placeholder with the hardware configuration generated by
the installer:

```bash
cp /etc/nixos/hardware-configuration.nix hosts/cipher/hardware-configuration.nix
```

Confirm that the copied file contains entries for `/`, `/boot`, and any swap or
encrypted devices created by the installer. Then enter the repository's
development shell and activate the system:

```bash
nix develop -c just switch
```

Reboot after the first successful activation so the NVIDIA modules, login
manager, user shell, and all system services start from the new generation.

## TX-02 font

TX-02 is licensed separately and is not stored in this repository. Copy all of
your licensed TX-02 font files into the local font directory and refresh the
font cache:

```bash
mkdir -p ~/.local/share/fonts/TX-02
cp /path/to/your/TX-02-font-files/* ~/.local/share/fonts/TX-02/
fc-cache -f
fc-match TX-02
```

Ghostty and Zed request TX-02. `Symbols Nerd Font` is installed declaratively as
the symbol fallback.

## Account setup

### 1Password and Git

1. Open 1Password and sign in.
2. In **Settings > Developer**, enable **Use the SSH agent**.
3. Add the existing SSH signing/authentication key to 1Password if it is not
   already present.
4. Install and enable the 1Password browser extension in Helium.
5. Allow 1Password system authentication when prompted.

Verify the agent and commit signing:

```bash
ssh-add -L
ssh -T git@github.com
mkdir -p /tmp/git-signing-test
git -C /tmp/git-signing-test init
git -C /tmp/git-signing-test commit --allow-empty -m "Verify 1Password signing"
git -C /tmp/git-signing-test log --show-signature -1
```

The configured signing key is the existing public key captured during the
migration. If the key in 1Password changes, update `programs.git.signing.key` in
`modules/home/git.nix`.

### Tailscale

Authenticate the machine interactively:

```bash
sudo tailscale up
tailscale status
```

The machine is configured as a client and can use exit nodes. It does not
advertise routes or act as an exit node.

### Dropbox

Dropbox starts with the Plasma graphical session. Follow the browser
authentication flow on first login; browser launches now go through Helium.
The normal synced folder is `~/Dropbox`.
The `~/.dropbox-dist` directory contains Dropbox client runtime files, not your
synced data. Check the service with:

```bash
systemctl --user status dropbox
journalctl --user -u dropbox -b
```

The upstream Dropbox Linux client self-updates outside the Nix store.

### Remaining applications

Open Steam, Helium, Discord, TIDAL Hi-Fi, Telegram, Zed, VS Code, and
Yubico Authenticator once and complete their normal sign-in flows. Steam
compatibility settings can select GE-Proton, which is installed declaratively.

## Hardware checks

The monitor was connected to the RTX 5070 when this configuration was created.
After rebooting, verify that Plasma is using Wayland and that NVIDIA rendering is
working:

```bash
echo "$XDG_SESSION_TYPE"
nvidia-smi
glxinfo -B
vulkaninfo --summary
```

`XDG_SESSION_TYPE` should report `wayland`. The AMD integrated GPU remains
available through `amdgpu`, but PRIME laptop switching is intentionally not
configured for this desktop.

To verify the YubiKey stack:

```bash
ykman list
systemctl status pcscd.socket
```

## Day-to-day maintenance

The `justfile` is the supported interface for routine work. Run `just` to list
the available commands:

```bash
cd ~/dots
just
```

Format and validate changes before activating them:

```bash
just fmt
just check
just build
```

Test a generation for the current boot or switch it permanently:

```bash
just test
just switch
```

`just test` and `just switch` refuse to activate unless the running hostname is
`cipher`. The zsh alias `rebuild` runs `just switch`.

Update inputs separately so the lock-file changes can be reviewed before
building or activation:

```bash
just update
git diff flake.lock
just check
just build
```

Update one input with `just update nixpkgs` or `just update home-manager`.

The repository has optional direnv integration. Run `direnv allow` once from
`~/dots` to load the development shell automatically when entering it.

Automatic garbage collection removes generations older than 30 days weekly.
Manual cleanup is available with:

```bash
just clean
```

## Recovery and rollback

Select an older generation from the systemd-boot menu if a new configuration
does not boot. From a working terminal, roll back the active system generation:

```bash
sudo nixos-rebuild switch --rollback
```

To test a change for only the current boot without making it the default:

```bash
just test
```

Home Manager creates `*.backup` files instead of overwriting conflicting files
during activation. Review and remove those backups after confirming the managed
configuration is correct.
